# Alice Miner v0.6.6 — release notes

> A **correctness** release over v0.6.5 (`c5330e4`), focused on one thing:
> **`stop` must actually stop, and must never claim more than it verified.**
> **Windows users should upgrade** — on Windows, `stop` could leave the mining
> engine running (still using your GPU and power) while printing "No orphan
> left", and after a crash it could report success forever without ever
> stopping anything. Also: the share counter no longer counts engine log
> numbers as shares, and the region/endpoint-lock notice now speaks your UI
> language. No change to the mining lanes, proof-of-possession, rewards, or
> auto-update. Still a **credit-only test build** — see the honesty note at
> the bottom. `min_supported` stays **0.3.0** (older clients get a one-tap
> auto-update, never a hard block).

## English

Alice Miner **v0.6.6** is a correctness release. Almost all of it is one
theme: when you press **Stop**, the miner must really stop, and whatever the
client tells you afterwards must be something it actually checked. Three
separate Windows bugs let a stopped miner keep running — or let the client
claim a clean stop it never verified — and the same class of false claim
existed in a quieter form on macOS and Linux. All of them are fixed.

**1. On Windows, `stop` no longer leaves the mining engine running.**
The client spawns a third-party engine (SRBMiner and friends) as a child
process. On Windows, killing the parent did **not** kill that child: the engine
survived, kept using your GPU, kept drawing power and making heat, and kept
your machine loaded long after you thought you had stopped mining — and the only
way to notice was Task Manager. v0.6.6 binds every spawned engine to a **Windows
Job Object** created with `KILL_ON_JOB_CLOSE`, so the operating system itself
terminates the child the moment the parent goes away — including if the client
is killed, crashes, or is force-closed. The cleanup path is hardened to match:
`taskkill` now uses `/T` so it takes the whole process tree, and the deprecated
`wmic` probe (absent or disabled on current Windows builds) was replaced with
PowerShell `Get-CimInstance`. This is verified on real Windows CI, not just in
theory — a test spawns a real child and asserts the OS tears it down.

**2. `stop` never reports a success it did not verify.**
The old code treated "I could not check" and "it is gone" as the same answer, so
any probe that failed to run read as a clean stop. Worst case: after a crash
left a stale pid file behind, `stop` would report success **permanently** while
never stopping anything at all. v0.6.6 makes process liveness an explicit
**tri-state — Alive / Dead / Unknown** — with a decision table
(`classify_tasklist`) mapping each possible `tasklist` outcome to exactly one of
the three, and Unknown is never silently promoted to Dead. A stale pid file is
taken over only when the previous owner is *positively* Dead; a live owner is
still respected, so two miners can't fight over one machine.

**3. The orphan sweep now runs on Windows, and looks for the right thing.**
The last-resort sweep that catches an engine which outlived its parent was
Unix-only, so on Windows nothing ever swept. It now runs on Windows too, and it
matches on the **engine path the client actually recorded when it launched**
rather than a guessed process name — so it finds the engine you started and
can't mistake an unrelated program for it.

**4. Share counts are no longer inflated by engine log lines.**
The engine's console output contains numbers that are not shares — `cuda:0`,
`power:120`, `gpu-a:0` and similar device/telemetry fields. The old parser
matched loosely and folded some of them into your accepted-share count, which
made the local counter drift upward away from the truth. v0.6.6 parses with a
**word-boundary allowlist** so only real accepted-share reports count. A second
guard, `fold_cumulative`, handles the engine's cumulative counter honestly: a
**rise is adopted immediately**, but a **fall requires a second, corroborating
reading** before it is accepted — so a single garbled line can neither inflate
nor silently erase your count. This is a local display/telemetry fix; it does
not change what the server credits you.

**5. The same false "no orphan left" on macOS and Linux is fixed too.**
The Unix path had the quieter twin of bug 2: `pgrep` exits **1** when it simply
found nothing and **≥2** when the scan itself failed, and the old code read both
as "nothing there". A blocked or failed scan therefore printed a confident "No
orphan left". `classify_pgrep` now distinguishes the three cases — `0` = found
matches, `1` = a real answer of *no match*, `≥2` = **the scan did not run** —
and only the genuine no-match prints the clean claim.

**6. The GUI now tells you what `stop` actually did — with exit codes.**
Pressing Stop in the desktop app used to be fire-and-forget: the GUI never saw
the CLI's output or its exit status, so a failed or unverified stop looked
identical to a clean one. v0.6.6 surfaces the CLI's stderr and exit code, and
gives the two honest partial outcomes their own codes:

| code | meaning | GUI |
|---|---|---|
| `0` | stopped, everything verified | normal |
| `3` | **could not confirm** — the miner may still be running | warning |
| `4` | **stopped**, but one cleanup check could not run | calm note, not a warning |

Exit code is the only channel that survives translation (the CLI's stderr is
bilingual), which is why the distinction is a number and not a phrase. For
scripts: **`0` and `4` both mean stopped; `3` means it may still be running.**
A scan gap never masks a worse outcome — if anything else was unverified, you
get `3`, not `4`.

**7. The region / endpoint lock notice is now localized.**
The Layer-B status line for a locked endpoint was an English string baked in
where it was produced, so a Chinese-locale user saw English, and switching the
UI language left the old text in place. Telemetry now carries a **message key
plus arguments**, and the GUI renders the sentence in whatever language is
currently selected — "Endpoint locked · 600s stalled" / "节点已锁定 · 600s 无进展"
— and re-renders correctly when you switch languages. The XMR fixed pool no
longer borrows PRL's "region failover" wording (it has no regions to fail over
to); it just says the endpoint is locked. The line no longer jumps between one
and two rows, and the full endpoint moved into the tooltip. Older CLIs that
send only the old plain-text message still display correctly.

### Thanks
Thanks to the tester who reported the Windows stop behaviour with enough detail
to reproduce all three bugs — the orphaned engine, the permanent false success
after a crash, and the drifting share count. A stop button that lies is worse
than no stop button, and none of these were visible from inside the app.

## 中文

Alice Miner **v0.6.6** 是一个正确性版本。它几乎只有一个主题:当你按下 **停止** 时,矿工
必须真的停下来;而之后客户端告诉你的每一句话,都必须是它真正检查过的。三个各自独立的
Windows bug 会让一个"已停止"的矿工继续运行 —— 或者让客户端宣称一次它从未验证过的干净
停止 —— 同一类假宣称在 macOS 与 Linux 上也以更安静的形式存在。它们全部已修复。

**1. 在 Windows 上,`stop` 不再把挖矿引擎留着继续跑。**
客户端会把第三方引擎(SRBMiner 之类)作为子进程启动。在 Windows 上,杀掉父进程**并不会**
杀掉那个子进程:引擎活了下来,继续占用你的 GPU、继续耗电发热,在你以为早已停止挖矿之后
仍让你的机器满载 —— 而唯一能发现它的办法是打开任务管理器。v0.6.6 把每一个启动的引擎都绑定
到一个用 `KILL_ON_JOB_CLOSE` 创建的 **Windows Job Object** 上,于是操作系统本身会在父进程
消失的那一刻终止子进程 —— 包括客户端被杀死、崩溃或被强制关闭的情况。清理路径也同步加固:
`taskkill` 现在带 `/T`,因此会带走整棵进程树;已废弃的 `wmic` 探测(在当前 Windows 版本上
可能不存在或被禁用)换成了 PowerShell 的 `Get-CimInstance`。这不是纸面推理 —— 真实的
Windows CI 上有一个测试会启动真实子进程,并断言操作系统把它连坐清除。

**2. `stop` 绝不报告任何它没有验证过的成功。**
旧代码把"我没能检查"和"它已经没了"当成同一个答案,于是任何跑不起来的探测都会被读作一次干净
的停止。最坏的情况:一次崩溃留下陈旧的 pid 文件之后,`stop` 会**永久地**报成功,却其实什么
都没停。v0.6.6 把进程存活变成显式的**三态 —— Alive / Dead / Unknown**,并用一张决策表
(`classify_tasklist`)把每一种可能的 `tasklist` 结果映射到三者之一,而 Unknown 绝不会被
悄悄升级成 Dead。陈旧的 pid 文件只有在原主人**确定** Dead 时才会被接管;活着的主人仍会被
尊重,因此两个矿工不会为一台机器打架。

**3. 孤儿扫描现在会在 Windows 上运行,并且找对了东西。**
那个用来兜底、抓住"活得比父进程还久"的引擎的扫描,过去只在 Unix 上存在,所以 Windows 上
从来没扫过。它现在也会在 Windows 上运行,并且是按**客户端启动时真正记录下来的引擎路径**去
匹配,而不是靠猜进程名 —— 因此它能找到你启动的那个引擎,也不会把无关程序错认成它。

**4. 份额计数不再被引擎日志行灌水。**
引擎的控制台输出里有一些并不是份额的数字 —— `cuda:0`、`power:120`、`gpu-a:0` 之类的设备
与遥测字段。旧的解析器匹配得太宽松,把其中一些折算进了你的已接受份额计数,使本地计数器逐渐
向上偏离真实值。v0.6.6 改用**词边界白名单**解析,只有真正的已接受份额报告才会计数。第二道
护栏 `fold_cumulative` 则诚实地处理引擎的累计计数器:**上升立即采纳**,而**下降必须有第二条
互相印证的读数**才被接受 —— 因此单独一行乱码既不能把你的计数灌高,也不能悄悄把它抹掉。这是
本地显示/遥测层面的修复,不改变服务端给你记的账。

**5. macOS 与 Linux 上同样的假"没有残留进程"也一并修了。**
Unix 路径上有 bug 2 的安静版孪生:`pgrep` 在**确实什么都没找到**时退出 **1**,在**扫描本身
失败**时退出 **≥2**,而旧代码把两者都读作"什么都没有"。于是一次被阻止或失败的扫描,反而会
打印出一句自信的"没有残留进程"。`classify_pgrep` 现在区分三种情况 —— `0` = 找到匹配,
`1` = 一个真实的*没有匹配*的答案,`≥2` = **扫描没有跑起来** —— 只有真正的"没有匹配"才会
打印那句干净的结论。

**6. GUI 现在会告诉你 `stop` 究竟做了什么 —— 用退出码。**
在桌面应用里按停止,过去是"发射后不管":GUI 从来看不到 CLI 的输出,也看不到它的退出状态,
于是一次失败的或未经验证的停止,看起来和一次干净的停止一模一样。v0.6.6 会把 CLI 的 stderr
与退出码透出来,并给两种诚实的"部分结果"各自的编码:

| 退出码 | 含义 | GUI |
|---|---|---|
| `0` | 已停止,全部验证通过 | 正常 |
| `3` | **无法确认** —— 矿工可能仍在运行 | 警告 |
| `4` | **已停止**,但有一项清理检查没能跑起来 | 平静的说明,不是警告 |

退出码是唯一能穿过翻译存活下来的通道(CLI 的 stderr 是双语的),这也正是这个区分被做成一个
数字而不是一句话的原因。给脚本:**`0` 和 `4` 都表示已停止;`3` 表示可能仍在运行。** 扫描
缺口绝不会掩盖更糟的结果 —— 只要还有别的东西未经验证,你拿到的就是 `3`,不是 `4`。

**7. 区域 / 节点锁定提示现在会本地化。**
锁定节点的 Layer-B 状态行,过去是在产生它的地方就写死的英文字符串,因此中文界面的用户看到的
是英文,而且切换界面语言之后旧文本还留在原地。遥测现在传的是**消息键加参数**,由 GUI 用当前
选中的语言把句子渲染出来 —— "Endpoint locked · 600s stalled" / "节点已锁定 · 600s 无进展"
—— 并且在你切换语言时会正确重新渲染。XMR 固定矿池不再套用 PRL 那套"region failover(区域
故障切换)"的措辞(它根本没有可切换的区域),而只是说明该节点已锁定。这一行不再在一行与两行
之间跳动,完整的 endpoint 移进了 tooltip。只发送旧式纯文本消息的老 CLI 仍能正确显示。

### 致谢
感谢那位把 Windows 停止行为报告得足够详细、以致三个 bug 全部可复现的测试者 —— 残留的引擎、
崩溃之后永久的假成功、以及逐渐偏移的份额计数。一个会说谎的停止按钮比没有停止按钮更糟,而这些
问题从应用内部一个都看不出来。

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.6, like v0.6.0 through v0.6.5, is a **DRY / credit-only test
build**. It really mines and shows your live hashrate and **accepted shares as
credit**, but **`paid_acu = 0` — no real money is paid, no cryptocurrency and no
fiat changes hands, and nothing here is a promise, projection, or guarantee of
earnings, rewards, or returns.** Everything in this release is correctness and
honesty — making `stop` actually stop, making the client refuse to claim what it
did not verify, and counting shares accurately in the local display; none of it
changes the fact that this build settles credit only. Note that the share-count
fix (item 4) corrects a **local** counter that could read high; the server's
ledger was always the authority and is unaffected.

显示实时算力与**以 credit 记账的已接受份额**,但 **`paid_acu = 0` —— 不发放任何真钱,不涉及
任何加密货币或法币,本文档中的任何内容都不构成对收益、奖励或回报的承诺、预测或保证。** 本版本
里的一切都是正确性与诚实 —— 让 `stop` 真的停下来、让客户端拒绝宣称它没有验证过的事、让本地
显示的份额计数准确;这些都不改变本版本只结算 credit 这一事实。请注意,份额计数修复(第 4 项)
纠正的是一个可能偏高的**本地**计数器;服务端账本一直是唯一权威,且不受影响。
