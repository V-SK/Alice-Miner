## English

Alice Miner **v0.6.3** is a miner-experience release over v0.6.2. Same mining
lanes, proof-of-possession, credit-only rewards, and ed25519-signed auto-update.
The headline is a fully-managed **bring-your-own-miner** path — point your own
(even closed-source) pearlhash rig at Alice, and the client handles the rest —
plus a real fix to the "Stopping…" that never finished, and more of the app
speaking clean Chinese. Every item traces back to external testers running v0.6.2
on real hardware.

**1. Bring your own miner — fully managed (form A, `MinerBackend::Custom`).**
Some testers run a third-party or closed-source pearlhash miner that gets a bit
more out of their card than the bundled engine. You can now hand that binary to
Alice and let the CLI manage the whole session: **enter your reward address, pick
a region, and mine.** The custom backend reuses the bundled shell *verbatim* — the
region-bound proof-of-possession handshake (OOB enrollment for the XMR-PoP lane),
the `<address>.<worker>` login with your reward key, and the shared payout-enroll
and PoP-refresh loops. Only the binary and its argv shape differ. Because a
bring-your-own binary is not SHA-pinned, running it is an **explicit opt-in**: you
acknowledge once that it is unverified, and every start prints a loud reminder.
The private key never leaves your machine; the child only ever sees the public
address.

**2. Detect installed miners + a fuller `setup` wizard.**
`setup` now walks the whole first run and can **auto-detect miners already on your
box** — it scans `$PATH` and the common install dirs (top level and one level
deep, bounded), probes each candidate's `--version`, and matches it to a
compatible lane. It is honest by construction: an unknown binary is simply *not*
claimed as detected, never guessed. The wizard lets you choose your miner program
— **bundled** (recommended, SHA-pinned, default), **custom** (bring-your-own,
form A above), or **companion-only** (form B: you run your own rig elsewhere and
the CLI holds only the PoP) — pick or type a region, and, when you have no reward
address yet, generate a fresh identity with a single `[Y/n]`. The whole thing also
runs non-interactively from one command line (`--miner`, `--miner-bin`,
`--miner-preset`, `--miner-arg-template`, `--i-understand-unverified`,
`--region`). Unknown / unreadable miner output degrades to "running, telemetry
unavailable" — the client never fabricates a hashrate for a format it can't read.

**3. Honesty gate hardening (custom-miner argv).**
The custom backend runs every rendered command line through the same honesty gate
as the bundled engine before spawning: **no foundation `prl1p…` address, no
upstream-pool host, no core IP, no seed material**, and — for a pearlhash lane —
**only `*.aliceprotocol.org` relay hosts**. A subtle gap was closed here: the gate
scrubs a long PoP password (a public base64 signature) out of the argv first, so a
signature that happens to contain `0x`/`prl1p` can't false-trip it — but the
default XMR/RVN stratum password is the literal `"x"`, and blanket-scrubbing that
would erase every `x` (in `supportxmr`, `kryptex`, the `0x` hex probe…) and
silently blind the scan. The scrub now only masks a password long enough to
plausibly be a secret (≥ 6 chars); a short one is left in place, so a real
key/host leak can never slip past. Covered by a new regression test.

**4. The Stop button now converges — no stuck "Stopping…", no false "Idle".**
On the CLI-in-terminal (GPU-persistence) path, pressing Stop could leave the GUI
pinned at "Stopping…" forever even after the CLI/xmrig had exited: the CLI writes a
final idle snapshot on its way out, and every ~900 ms poll re-read it and re-armed
the staleness clock, so the app never converged. Stop now converges to **Idle** the
moment the definitive down-signal fires — **both** the CLI-parent pid
(`miner-cli.pid`) and the engine-child pid (`miner-child.pid`) are gone — and
sweeps a legacy `miner.pid` on the way. Just as important, that convergence is
**gated on pid-absence**: a transient Layer-B failover / in-place restart / child
crash drives a lane to Idle or Error *while the CLI parent is still live*, and the
GUI must NOT read that as "stopped." It now keeps polling through those transients,
surfaces a crash's Error instead of swallowing it to Idle, and recovers to Running
when the lane comes back — so you never see a false "Idle while still mining."

**5. More of the app in clean Chinese + smaller polish.**
In 中文 mode the Home, Dashboard, and Settings screens still showed hardcoded
English residuals; they now route through the same `tr!(en, zh)` mechanism and each
renders a single clean language — CTA labels and sub-lines, stat-card titles,
connection and lane rows, the software-update panel, the region row, the PRL
return-address label. The reward/credit/payout-adjacent copy stays on the audited
bilingual `strings.rs` surface (both language literals still scanned by the honesty
test), and the "pending · 待发放" framing is preserved everywhere. Plus: the small
"Stop mining" button under the hero now shows a pointing-hand cursor on hover so it
reads as clickable, and the `doctor --lane prl` "a removed `fi` relay leaked in"
hint is now version-neutral ("this build's compiled defaults") so it can't drift
with the release number.

### Thanks
Every change above came from external testers who ran v0.6.2 on real hardware and
reported carefully — above all the M4 Max tester whose deep feedback surfaced both
the "Stop stuck at Stopping…" convergence bug and the Chinese-mode localization
gaps, and the testers who asked to run their own tuned pearlhash rigs under Alice's
management. Thank you.

## 中文

Alice Miner **v0.6.3** 是 v0.6.2 之上的矿工体验版。挖矿 lane、proof-of-possession、
credit-only 奖励、ed25519 签名自动更新全部不变。头条是一条全托管的**自带矿机**路径 ——
把你自己的(甚至闭源的)pearlhash 矿机指向 Alice,其余交给客户端 —— 外加真正修好那个
永远停不下来的"停止中…",以及更多界面讲出干净的中文。每一项都源自在真实硬件上运行
v0.6.2 的外部测试者反馈。

**1. 自带矿机 —— 全托管(形态 A,`MinerBackend::Custom`)。**
有些测试者用第三方或闭源 pearlhash 矿机,能比自带引擎多榨出一点算力。现在你可以把那个
二进制交给 Alice,让 CLI 托管整个会话:**输入你的收款地址、选一个区域,即可开挖。**
自定义后端**逐字复用**自带那套外壳 —— 区域绑定的所有权证明握手(XMR-PoP 通道走 OOB
报名)、用你的收款密钥做的 `<地址>.<worker>` 登录、以及共享的 payout-enroll 与 PoP 刷新
循环。不同的只有二进制本身和它的 argv 形状。由于自带二进制不做 SHA 锁定,运行它是一次
**显式选择加入**:你确认一次它未经验证,之后每次启动都会打印醒目提醒。私钥绝不离开本机,
子进程只会看到公开地址。

**2. 检测已安装的矿机 + 更完整的 `setup` 向导。**
`setup` 现在会走完整个首次上手流程,并能**自动检测你机器上已有的矿机** —— 它扫描
`$PATH` 与常见安装目录(顶层 + 向下一层,有界),对每个候选探测 `--version`,并匹配到
一条兼容 lane。它天生诚实:未知二进制绝不被"猜"成已检测,只会如实不认领。向导让你选择
矿机程序 —— **bundled**(推荐、SHA 锁定、默认)、**custom**(自带,即上面的形态 A)、或
**companion-only**(形态 B:矿机在别处自己跑,CLI 只持有 PoP)—— 选择或输入区域;当你还
没有收款地址时,用一个 `[Y/n]` 生成新身份。整套流程也可用一行命令非交互完成(`--miner`、
`--miner-bin`、`--miner-preset`、`--miner-arg-template`、`--i-understand-unverified`、
`--region`)。未知/不可读的矿机输出会降级为"运行中,遥测不可用" —— 客户端绝不为读不懂的
格式编造算力。

**3. 诚实门加固(自定义矿机 argv)。**
自定义后端在启动前,会像自带引擎一样,把每一条渲染出的命令行都过一遍同一个诚实门:
**没有基金会 `prl1p…` 地址、没有上游矿池主机、没有核心 IP、没有种子材料**,并且 —— 对
pearlhash 通道 —— **只允许 `*.aliceprotocol.org` 中继主机**。这里补上了一个微妙的漏洞:
诚实门会先把长的 PoP 密码(一段公开的 base64 签名)从 argv 中擦除,好让一段恰好含
`0x`/`prl1p` 的签名不会误触发它 —— 但 XMR/RVN 默认 stratum 密码是字面量 `"x"`,一刀切地
擦掉它会抹掉每一个 `x`(在 `supportxmr`、`kryptex`、`0x` 十六进制探针里…)从而悄悄使扫描
失明。现在擦除只会遮蔽长到足以像是秘密的密码(≥ 6 字符);短的原样保留,因此真正的
密钥/主机泄漏永远漏不过去。有新增回归测试覆盖。

**4. 停止按钮现在会收敛 —— 不再卡"停止中…",也不误报"空闲"。**
在 CLI-在-终端(GPU 常驻)路径上,按下停止后,即便 CLI/xmrig 已退出,GUI 也可能永远卡在
"停止中…":CLI 在退出途中会写一份最终的空闲快照,而每约 900 ms 的轮询会一再读到它并重置
过期时钟,于是应用永不收敛。现在停止会在那个决定性的"已停"信号出现的一刻收敛到**空闲**
—— **CLI 父进程 pid(`miner-cli.pid`)与引擎子进程 pid(`miner-child.pid`)双双消失** ——
并顺手清扫遗留的 `miner.pid`。同样重要的是,这个收敛**以 pid 不存在为闸门**:一次瞬态的
第二层故障切换 / 原地重启 / 子进程崩溃会在 *CLI 父进程仍然存活* 时把某条 lane 驱到空闲或
错误,而 GUI 绝不能把它读成"已停止"。它现在会穿过这些瞬态继续轮询,把崩溃的错误如实呈现
而非吞成空闲,并在 lane 恢复时回到运行中 —— 你再也不会看到"仍在挖矿却显示空闲"的假象。

**5. 更多界面讲干净中文 + 若干打磨。**
在中文模式下,Home、Dashboard、Settings 三屏仍残留硬编码英文;它们现在都走同一个
`tr!(en, zh)` 机制,各自渲染出单一干净的语言 —— CTA 标签与副行、统计卡标题、连接与 lane
行、软件更新面板、区域行、PRL 返现地址标签。奖励/credit/payout 相邻的文案仍留在经审计的
双语 `strings.rs` 面上(两种语言字面量仍被诚实测试扫描),各处"pending · 待发放"框架保持
不变。此外:主视觉下方那个小小的"停止挖矿"按钮,现在悬停会显示手型光标,读起来像可点击;
`doctor --lane prl` 那条"某个已移除的 `fi` 中继泄漏进来"的提示现在版本中性("本构建的编译
默认值"),因此不会随发布号漂移。

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.3, like v0.6.0 / v0.6.1 / v0.6.2, is a **DRY / credit-only test
build**. It really mines and shows your live hashrate and **accepted shares as
credit**, but **`paid_acu = 0` — no real money is paid, no cryptocurrency and no
fiat changes hands, and nothing here is a promise, projection, or guarantee of
earnings, rewards, or returns.** Mining is permissionless with a bare Alice address
— no enrollment and no proof-of-possession are required for the open (XMR/RVN)
lanes; the pearlhash lanes use a possession proof only to bind shares to your
address, not to gate payment. A bring-your-own custom miner runs under the exact
same terms — the same honesty gate scrubs its command line, and it earns credit
only. The purpose of this build is exactly to let testers exercise the
download → configure → mine → view-payout path on real machines and confirm these
fixes, at zero real-money risk.

它会真实挖矿,显示实时算力与**以 credit 记账的已接受份额**,但 **`paid_acu = 0` ——
不发放任何真钱,不涉及任何加密货币或法币,本文档中的任何内容都不构成对收益、奖励或回报的
承诺、预测或保证。** 挖矿用一个裸 Alice 地址即可,是 permissionless 的 —— 开放
(XMR/RVN)通道无需报名、无需 proof-of-possession;pearlhash 通道用所有权证明只是为了把

诚实门会擦洗它的命令行,而且它只赚取 credit。本版本的目的正是让测试者在真实机器上跑通
