# Alice Miner v0.6.4 — release notes

> A focused **bug-fix** roll-up over v0.6.3 (`51aafd0`), for the PRL (pearlhash)
> payout path. Still a **credit-only test build** — see the honesty note at the
> bottom. `min_supported` stays **0.3.0** (older clients get a one-tap
> auto-update, never a hard block).

> 收款路径。仍是 **credit-only 测试版**(见文末诚实声明)。`min_supported` 保持

## English

Alice Miner **v0.6.4** is a small, targeted bug-fix release over v0.6.3. Same
mining lanes, proof-of-possession, credit-only rewards, and ed25519-signed
auto-update — nothing about the economics or the honesty model changes. Two
real defects on the **PRL / pearlhash payout path** are fixed, both traced to
external testers running v0.6.3 on real hardware.

**1. PRL payout-address binding now actually lands (enroll-nonce contract).**
The 15% PRL return goes to *your* address only after the client completes a
one-time **enroll** handshake: fetch a single-use nonce, sign it, and POST the
binding. On v0.6.0–v0.6.3 that handshake silently never completed. The server
(`POST /acp/m4/enroll/nonce`) returns the nonce under the key `enroll_nonce`,
but the client only deserialized a plain `nonce` field — so parsing failed with
"missing field `nonce`" on **every** real response, the enroll completion POST
was never sent, and the payout-address binding never landed. It failed open (it
never stopped the lane or lost credit), which is exactly why it stayed invisible.

  v0.6.4 resolves the nonce from **two** optional fields — `enroll_nonce`
  (canonical) and `nonce` (compat) — and takes whichever is present. This
  accepts the pre-hotfix server body (`enroll_nonce` only), a plain-`nonce` body,
  **and** the steady-state body that carries both keys. (A single serde
  `alias` would have been wrong: when both keys arrive, serde rejects the body
  with "duplicate field `nonce`" — so the alias client would break against the
  very server it pairs with. The two-field `.or()` shape, mirroring the existing
  challenge handshake in the same file, is correct for all three shapes.) The
  GPU-PRL enroll task also now logs an enroll failure's reason instead of
  swallowing it, so a future contract drift can't go fully silent.

  Paired with an additive server-side hotfix that emits **both** keys
  byte-identically, this also repairs the **already-deployed** v0.6.0–v0.6.3
  clients: they read the plain `nonce` the server now includes, so their
  binding completes without an update. v0.6.4 is the forward-correct client that
  works against both the pre- and post-hotfix server.

**2. GPU-PRL region failover now recovers past an unhealthy region.**
The Layer-B failover watchdog used to give up the instant a single region's
rebuild failed: it went to Error and froze the lane on that region, showing a
"retrying other regions" status that never actually retried. That is the RTX
4090 tester's exact symptom — Asia jittered, the client auto-switched to US, the
US relay's control plane was unhealthy, and the lane stuck on US with the
failover count climbing but the endpoint never rotating. Root cause: the
pre-flight probe only checks TCP reachability (`:3340`), so a region whose
stratum port answers while its PoP/control plane is down still gets picked, and
the single-shot handler dead-ended on it.

  v0.6.4 replaces that single-shot path with a **recovery loop** that tries every
  other region and, on a rebuild failure, advances to the **next** one instead of
  erroring out. Attempts are ordered by the remembered `last_good` region first
  (resume where shares were actually landing), then the rotation order, then a
  final in-place retry of the stalled region (a pure jitter can recover). The
  status endpoint tracks the cursor across every attempt, so it never freezes on
  a dead region; the honest labels are `auto-failover: <from> → <to>` on a real
  switch, "region recovered — resuming" on an in-place resume, and a clear
  "all regions unavailable" **only** when every region fails a full round — never
  the lying "retrying" line with nothing left to try. An explicit `--region`
  **lock** still retries in place and never silently rotates away; an
  auto-selected region keeps the full set and rotates freely (an auto-selected US
  never hardens into a lock). The restart budget is still charged once per stall,
  so trying several regions is not a restart storm, and all prior
  failover / lock / budget invariants hold.

### Thanks
Both fixes came from external testers who ran v0.6.3 on real hardware and
reported carefully — the Shanghai PRL tester whose enroll never bound the payout
address, and the RTX 4090 tester whose Asia-to-US failover dead-ended on an
unhealthy US relay. Thank you.

## 中文

Alice Miner **v0.6.4** 是 v0.6.3 之上一个小而聚焦的 bug 修复版。挖矿 lane、
proof-of-possession、credit-only 奖励、ed25519 签名自动更新全部不变 —— 经济模型与
诚实模型均无改动。本版修复了 **PRL / pearlhash 收款路径**上的两个真实缺陷,两者都源自
在真实硬件上运行 v0.6.3 的外部测试者反馈。

**1. PRL 收款地址绑定现在真正生效(enroll-nonce 契约)。**
15% 的 PRL 返现只有在客户端完成一次性的 **enroll** 握手后,才会打到 *你的* 地址:
取一个单次 nonce、签名、再 POST 绑定。在 v0.6.0–v0.6.3 上,这个握手悄悄地从未完成过。
服务端(`POST /acp/m4/enroll/nonce`)把 nonce 放在 `enroll_nonce` 键下返回,而客户端
只反序列化了一个普通的 `nonce` 字段 —— 于是**每一个**真实响应都以"缺少字段 `nonce`"
解析失败,enroll 完成的 POST 从未发出,收款地址绑定从未落地。它是 fail-open 的
(从不停 lane、也不丢 credit),这正是它一直不可见的原因。

  v0.6.4 从**两个**可选字段解析 nonce —— `enroll_nonce`(规范键)与 `nonce`(兼容键)
  —— 取其中存在的那个。这能接受 hotfix 前的服务端响应体(只有 `enroll_nonce`)、只有
  普通 `nonce` 的响应体,**以及**同时携带两个键的稳态响应体。(单个 serde `alias`
  是错的:当两个键同时到达时,serde 会以"duplicate field `nonce`"拒绝该响应体 ——
  于是 alias 版客户端会对它本该配套的那个服务端崩掉。采用两字段 `.or()` 形态,与同文件
  中已有的 challenge 握手一致,对上述三种形态都正确。)GPU-PRL 的 enroll 任务现在还会
  记录 enroll 失败的原因,而不是把它吞掉,这样未来若契约再漂移也不会完全静默。

  配合一个附加式的服务端 hotfix(同时按字节一致地发出**两个**键),这也修好了
  **已部署的** v0.6.0–v0.6.3 客户端:它们会读到服务端现在附带的普通 `nonce`,于是
  无需更新即可完成绑定。v0.6.4 是那个向前正确的客户端,对 hotfix 前后的服务端都能工作。

**2. GPU-PRL 区域故障切换现在能越过不健康的区域继续恢复。**
第二层故障切换看门狗过去只要某个区域的重建一失败就立刻放弃:它进入 Error 并把 lane
冻结在那个区域,显示一条"正在重试其他区域"却从未真正重试的状态。这正是那位 RTX 4090
测试者的确切症状 —— Asia 抖动,客户端自动切到 US,而 US 中继的控制平面不健康,于是
lane 卡在 US 上,故障切换计数一直上涨,端点却从不轮转。根因:预检探针只检查 TCP 可达性
(`:3340`),所以一个 stratum 端口能应答、但 PoP/控制平面已宕的区域仍会被选中,单发
处理器便在它上面走进死胡同。

  v0.6.4 用一个**恢复循环**取代那条单发路径:它会尝试每一个其他区域,并在某次重建失败时
  **前进到下一个**而不是报错退出。尝试顺序优先记住的 `last_good` 区域(回到份额真正在
  落地的地方),然后是轮转顺序,最后再原地重试一次卡住的区域(纯抖动是可以恢复的)。
  状态端点会在每一次尝试间跟踪游标,因此绝不会冻结在一个已死的区域上;诚实的标签是:真正
  切换时 `auto-failover: <from> → <to>`、原地恢复时"region recovered — resuming"、
  只有当每个区域都在一整轮里失败时才给出明确的"all regions unavailable" —— 绝不再出现
  那条无路可退却还在"重试"的谎话。显式 `--region` **锁定**仍会原地重试、绝不悄悄轮转
  离开;自动选中的区域则保留整套集合、自由轮转(一个自动选中的 US 不会硬化成锁定)。重启
  预算仍是每次停滞只计一次,所以尝试多个区域不构成重启风暴,先前所有的
  故障切换 / 锁定 / 预算不变式均成立。

### 致谢
两处修复都来自在真实硬件上运行 v0.6.3 并认真反馈的外部测试者 —— 那位 enroll 从未绑定
收款地址的上海 PRL 测试者,以及那位 Asia 切到 US 后在不健康的 US 中继上走进死胡同的
RTX 4090 测试者。谢谢你们。

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.4, like v0.6.0 / v0.6.1 / v0.6.2 / v0.6.3, is a **DRY /
credit-only test build**. It really mines and shows your live hashrate and
**accepted shares as credit**, but **`paid_acu = 0` — no real money is paid, no
cryptocurrency and no fiat changes hands, and nothing here is a promise,
projection, or guarantee of earnings, rewards, or returns.** The two fixes above
repair how the client *binds* your PRL return address and how it *recovers*
across regions; they do not change the fact that this build settles credit only.
The PRL possession/enroll handshake binds shares to your address — it is not a
payment gate. The purpose of this build is exactly to let testers exercise the
download → configure → mine → view-payout path on real machines and confirm
these fixes, at zero real-money risk.

credit-only 测试版**。它会真实挖矿,显示实时算力与**以 credit 记账的已接受份额**,但
**`paid_acu = 0` —— 不发放任何真钱,不涉及任何加密货币或法币,本文档中的任何内容都不

PRL 返现地址、以及如何跨区域*恢复*;它们不改变本版本只结算 credit 这一事实。PRL 的
