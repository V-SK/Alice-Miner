# Alice Miner v0.6.5 — release notes

> A **polish + safety** roll-up over v0.6.4 (`8affc3e`): one wallet-safety
> guard, clearer errors and diagnostics, and two UX fixes. No change to the
> mining lanes, proof-of-possession, rewards, or auto-update. Still a
> **credit-only test build** — see the honesty note at the bottom.
> `min_supported` stays **0.3.0** (older clients get a one-tap auto-update,
> never a hard block).
> 在 v0.6.4(`8affc3e`)之上的一个 **打磨 + 安全** 汇总版:一处钱包安全护栏、更清晰的
> 报错与诊断、两处 UX 修复。挖矿 lane、proof-of-possession、奖励、自动更新全部不变。仍是
> **credit-only 测试版**(见文末诚实声明)。`min_supported` 保持 **0.3.0**(旧客户端一键
> 自动更新,绝不硬块)。

## English

Alice Miner **v0.6.5** is a small, targeted polish release over v0.6.4. The
economics and the honesty model are unchanged; every item below is about not
surprising you — protecting your wallet, telling you the truth in a status line
or an error message, and making the GUI and CLI agree with reality.

**1. `identity --create` can no longer silently overwrite your wallet.**
Running `identity --create` when a keystore already exists used to overwrite it
in place — the old address (and its funds) were gone with no prompt and no
backup. v0.6.5 refuses that overwrite by default: if a keystore is already
present, `--create` aborts with a clear message and a non-zero exit, and your
existing address is left byte-for-byte untouched. To intentionally replace it,
pass **`--force`**, which first writes a timestamped `.bak` of the old keystore
next to it, then generates the new one. On a non-interactive shell the guard
aborts rather than guessing. `import`, `paste`, and `show` are unaffected — this
guard is only on the one path that can destroy a key.

**2. A region **lock** is now a WARN, not a doctor "Fail".**
If you pin a mining region with `--region <name>`, `doctor` used to flag that as
a hard **Fail**, which made a perfectly healthy locked setup look broken and
dragged the overall readiness line down. v0.6.5 reports a locked region as a
**WARN** with a one-line fix hint (`--region auto` to re-enable auto-failover).
A WARN never counts toward the failure total, so `doctor`'s `ready` verdict, its
exit code, and its `--json` shape are all unchanged — machine consumers and the
background service see exactly what they saw before. The first time you lock a
region from `start`, you also get a single one-time stderr note explaining the
trade-off (you keep that region, you give up auto-failover); restarts inherit
the lock silently and don't nag.

**3. Clearer onboarding errors (enroll / PoP / companion).**
Enroll, proof-of-possession, and companion failures now go through the same
structured error formatter the rest of the CLI uses — a short *what happened*
line, a *why* line, and an *action* line pointing at the real fix (check your
region/relay, confirm you're on the allowlist, etc.), with the raw detail still
available in verbose mode. A new enroll/register classification means an
onboarding failure reads as "not yet on the allowlist / region unreachable"
instead of a bare stack of tokens. No earnings or fiat language ever appears in
these messages.

**4. `--version` and `doctor` now stamp the exact build.**
`alice-miner --version`, the `doctor` report header, and `doctor --json` now
carry the precise version, target triple, and OS — e.g.
`alice-miner 0.6.5 aarch64-apple-darwin (macos)`. This makes a bug report
unambiguous about which binary on which platform you ran, with **no file paths
printed** (the stamp never leaks your identity or keystore location). The
`doctor --json` output only *gains* a `build` object; every existing key is
untouched.

**5. The GUI re-attaches to a miner you started in a terminal.**
If you launched a miner from the CLI and then opened the desktop GUI, the GUI
used to show **Idle** even though mining was clearly running. v0.6.5 detects a
live terminal miner via its status snapshot's freshness plus a real
process-liveness check, and adopts that running state instead of showing a false
Idle. A dead or stale leftover is correctly *not* adopted (a stopped miner still
reads as Idle), and pid 0 is treated as not-alive on every platform so a
process-group address can't masquerade as a live miner.

**6. The unreleased RVN lane fails fast with a clear message.**
`--lane rvn` (KawPoW / Ravencoin) is **not** in this release — it's coming in a
later milestone (M7). Selecting it used to dead-end in a deep, opaque failure;
v0.6.5 rejects it immediately with a plain-language message ("the RVN lane is
not available in this release — it is coming in M7; use `--lane gpu` or
`--lane xmr` for now") and a clean usage exit code. RVN is also removed from the
lane list in `--help` so it no longer looks selectable.

**7. README examples all map to real commands.**
The CLI README documented commands and flags that don't exist in the binary.
Every example was checked against the actual command definitions: the stale
"(latest: v0.5.0)" install line now points at `/releases/latest` so it can't go
stale again, phantom commands and flags were removed, and the intro now
describes the two real roles this client supports (contribute compute as a
**shard** node, or **train**) instead of a removed third role. Docs-only — no
behavior change.

### Thanks
Thanks to the testers whose careful reports drove this round — the wallet-safety
guard in particular exists because overwriting a keystore in place is the kind
of one-keystroke mistake that only shows up once, and once is too many.

## 中文

Alice Miner **v0.6.5** 是 v0.6.4 之上一个小而聚焦的打磨版。经济模型与诚实模型均无改动;
下面每一项都是为了不让你意外 —— 保护你的钱包、在状态行或报错里对你说实话、让 GUI 与 CLI
和现实保持一致。

**1. `identity --create` 不再会悄悄覆盖你的钱包。**
在已存在 keystore 的情况下运行 `identity --create`,过去会原地覆盖它 —— 旧地址(以及其中
的资产)在没有任何提示、没有任何备份的情况下就没了。v0.6.5 默认拒绝这种覆盖:如果已经存在
keystore,`--create` 会带着清晰的提示与非零退出码中止,你现有的地址会被逐字节原样保留。若
确实要替换它,请传 **`--force`** —— 它会先在旁边写一份带时间戳的旧 keystore `.bak` 备份,
再生成新的。在非交互 shell 里,这道护栏会中止而不是瞎猜。`import`、`paste`、`show` 均不受
影响 —— 这道护栏只加在那唯一一条会销毁密钥的路径上。

**2. 区域**锁定**现在是 WARN,而不是 doctor 的 "Fail"。**
如果你用 `--region <名字>` 固定了挖矿区域,`doctor` 过去会把它标为硬 **Fail**,让一套完全
健康的锁定配置看起来像坏了,还把整体就绪状态拖下去。v0.6.5 把锁定区域报为 **WARN**,并附一行
修复提示(`--region auto` 重新启用自动故障切换)。WARN 从不计入失败总数,因此 `doctor` 的
`ready` 结论、退出码、以及 `--json` 结构全部不变 —— 机器消费者和后台服务看到的和以前一模
一样。你第一次从 `start` 锁定区域时,还会收到一条一次性的 stderr 说明,解释这个取舍(你保住
了那个区域,但放弃了自动故障切换);之后重启会静默继承这个锁定,不再唠叨。

**3. 更清晰的上手报错(enroll / PoP / companion)。**
enroll、proof-of-possession、companion 的失败现在都走 CLI 其余部分用的那套结构化报错
格式化器 —— 一行*发生了什么*、一行*为什么*、一行*该怎么办*(指向真正的修法:检查你的
区域/中继、确认你在允许名单里等),原始细节仍可在 verbose 模式查看。新增的 enroll/register
分类意味着一次上手失败会读作"尚未进入允许名单 / 区域不可达",而不是一堆裸的 token。这些
消息里从不出现任何收益或法币字样。

**4. `--version` 与 `doctor` 现在会标注确切的构建。**
`alice-miner --version`、`doctor` 报告表头、以及 `doctor --json` 现在都带上精确的版本、
目标三元组(target triple)与操作系统 —— 例如
`alice-miner 0.6.5 aarch64-apple-darwin (macos)`。这让 bug 报告能毫不含糊地说明你跑的是
哪个平台上的哪个二进制,且**不打印任何文件路径**(这个标记绝不泄露你的身份或 keystore 位置)。
`doctor --json` 输出只是*新增*一个 `build` 对象;每个已有的键都原样不动。

**5. GUI 会重新接管你在终端里启动的矿工。**
如果你从 CLI 启动了矿工、然后又打开桌面 GUI,GUI 过去会显示 **Idle**,尽管挖矿明明在跑。
v0.6.5 会通过状态快照的新鲜度加上一次真实的进程存活检查来探测在跑的终端矿工,并接管那个运行
状态,而不是显示一个假的 Idle。一个已死或陈旧的残留会被正确地*不*接管(已停止的矿工仍读作
Idle),并且 pid 0 在每个平台上都被当作"未存活",这样进程组地址就无法冒充一个在跑的矿工。

**6. 未发布的 RVN lane 会快速失败并给出清晰提示。**
`--lane rvn`(KawPoW / Ravencoin)**不在**本版本里 —— 它会在后续里程碑(M7)推出。过去选它
会走进一个很深、很晦涩的失败;v0.6.5 会立即用大白话拒绝它("RVN lane 在本版本尚不可用 ——
将在 M7 推出;现在请用 `--lane gpu` 或 `--lane xmr`"),并给出干净的 usage 退出码。RVN 也从
`--help` 的 lane 列表里移除,不再看起来可选。

**7. README 里的示例全部对应真实命令。**
CLI README 曾记录了一些二进制里并不存在的命令和 flag。每一条示例都对照实际的命令定义做了核对:
陈旧的 "(latest: v0.5.0)" 安装行现在指向 `/releases/latest`,不会再过期;幽灵命令和 flag 已
移除;开篇现在描述这个客户端真正支持的两种角色(作为 **shard** 节点贡献算力,或 **train**
训练),而不是一个已被移除的第三种角色。纯文档 —— 无行为改动。

### 致谢
感谢那些用认真反馈推动这一轮的测试者 —— 尤其是那道钱包安全护栏,之所以存在,是因为原地覆盖
keystore 正是那种只会犯一次、而一次就已太多的一键失误。

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.5, like v0.6.0 through v0.6.4, is a **DRY / credit-only test
build**. It really mines and shows your live hashrate and **accepted shares as
credit**, but **`paid_acu = 0` — no real money is paid, no cryptocurrency and no
fiat changes hands, and nothing here is a promise, projection, or guarantee of
earnings, rewards, or returns.** Everything in this release is polish, safety,
and clarity — a wallet-overwrite guard, honest status lines and error messages,
and a build stamp for bug reports; none of it changes the fact that this build
settles credit only. The purpose of this build is exactly to let testers
exercise the download → configure → mine → view-payout path on real machines at
zero real-money risk.

显示实时算力与**以 credit 记账的已接受份额**,但 **`paid_acu = 0` —— 不发放任何真钱,不涉及
任何加密货币或法币,本文档中的任何内容都不构成对收益、奖励或回报的承诺、预测或保证。** 本版本
里的一切都是打磨、安全与清晰 —— 一道钱包覆盖护栏、诚实的状态行与报错、以及用于 bug 报告的构建
标记;这些都不改变本版本只结算 credit 这一事实。本版本的目的正是让测试者在真实机器上跑通
"下载 → 配置 → 挖矿 → 查看 payout"链路,且零真钱风险。
