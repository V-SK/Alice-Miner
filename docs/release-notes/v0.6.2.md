## English

Alice Miner **v0.6.2** is a miner-experience release over v0.6.1. Same mining
lanes, proof-of-possession, credit-only rewards, and ed25519-signed auto-update —
what changes is how clearly the client tells you what it is doing, a real fix to
the Stop button, a first-run advisor, a bring-your-own-miner path, and a new
region. Every item traces back to external testers running v0.6.1 on real
hardware.

**1. Terminal ↔ Dashboard telemetry sync (GUI).**
When you run a miner from the terminal CLI, the desktop app now shows the same
live picture. The CLI mirrors its live snapshot to a small telemetry file (atomic
overwrite, never append; the credit-only Snapshot with no address-adjacent secret
and no `paid_acu`), and the GUI polls it ~every 900 ms and folds it into the
Dashboard through the existing snapshot path. The app reads **Running** the moment
the terminal launches (before the first snapshot), **Stopping** while a stop winds
down, and returns to **Idle** once the telemetry goes stale (>10 s — terminal
closed or CLI exited) instead of showing Running forever. The EN/中 toggle is now
mirrored into the shared core each frame, so the titlebar status pill and the
Settings labels localize to Chinese (the "中文模式仍是英文" report).

**2. The Stop button now really stops the miner (orphan-xmrig fix).**
An M4-Max tester reported "I pressed Stop, but xmrig is still pegged at ~1200 %
CPU." `stop` is now **orphan-safe** with a three-layer backstop, most-specific
first: the CLI parent pid (`miner-cli.pid`, the clean path), then the **engine
child** (`miner-child.pid`, written by the supervisor with the exact engine
binary path), then a unix last resort that matches ONLY our exact bundled xmrig
path. The GUI Stop now runs the bundled CLI `stop` (with these backstops) instead
of a dormant in-window engine, and best-effort stops the external miner on exit —
no double-mine, no orphaned xmrig. The layer-2 child-pid backstop is
**identity-verified before it kills**: it re-checks that the live pid's command
line still contains our recorded engine path (`ps` on unix, `wmic` on Windows,
fail-safe when unknown), so a stale pid file whose number the OS has since REUSED
for an unrelated process is left untouched — Stop can never signal an innocent
process. Engine-agnostic (xmrig / SRBMiner / kawpowminer / AlphaMiner); the legacy
pid-only file is tolerated.

**3. Region transparency + `doctor` diagnostics (GPU-PRL lane).**
A tester saw the PRL lane hop Asia → US and couldn't tell "Asia first, with
auto-failover" from "Asia locked." The effective region policy is now legible
everywhere, computed **without any network probe** (from persisted settings +
`ALICE_GPU_RELAY_REGION`, so showing it costs no round-trip and never
double-probes — the engine still runs the one real RTT probe at start).
`start --lane prl` prints the effective region **mode** line and the effective
**endpoint order** (bilingual). `doctor --lane prl` gains three lines — PRL region
mode, PRL region sources (`region_lock` / `last_good_region` /
`ALICE_GPU_RELAY_REGION`, and whether `ALICE_MINER_ENDPOINTS_JSON` is set,
presence only), and PRL effective endpoints. If a decommissioned `fi` relay ever
leaks in from a stale binary or an endpoints-JSON override, both the banner and
`doctor` flag it with the exact hint. The GUI gains a read-only "Region" status
row (there is no region PICKER — region is set via `start --region <tag>`).

**4. First-run mining guide (`guide`) + bilingual `mining-guide.md`.**
New `alice-miner guide` — an advisor that explains, in the first minute, how Alice
mining actually works (real shares of an existing coin, difficulty-weighted 6 h
emission split 70/15/15 across the GPU/CPU/ASIC pools), detects your hardware, and
recommends a lane — writing nothing and needing no identity (unlike `setup`). It
ships alongside a new bilingual `docs/mining-guide.md` walkthrough (how it works →
choose a lane → bring your own miner → platform notes/troubleshooting), all in the
credit-only honesty framing, with no upstream pool host, foundation address, or
core IP anywhere in the output.

**5. Bring your own third-party pearlhash miner (`companion`).**
The PRL/Alpha relays require a proof-of-possession that the official client proves
internally but a third-party rig can't. New `alice-miner companion` holds that
proof **without running any miner**: it unlocks your Alice key LOCALLY and runs
the `/m4/challenge → sign → /m4/verify` handshake on a refresh loop inside the
relay's allowlist TTL, keeping `(your address, device)` authorized while you point
your own rig at the same region relay. Your private key never leaves the machine.
The companion now **rejects an `--address` that isn't this box's signing
identity** — the relay verifies the PoP signature against the enrolled address's
pubkey, so enrolling any other address produced a signature it could never verify
and the rig looped forever on `code:24` (fail-safe but silent). A mismatch now
exits with a bilingual, actionable error that names both addresses and
disambiguates the separate PRL cashback address.

**6. New EU region (GPU-PRL / Alpha).**
`eu.aliceprotocol.org` is now **fully live** (certificate signed, behaviour
identical to `us` and `asia`) and joins the compiled region set. The pearlhash
regions are now **us / asia / eu**; EU nodes get a nearer relay automatically, and
you can pin it with `start --region eu` (or the companion's `--region eu`). The
change flows from a single source of truth (`REGION_HOSTS`) to every derived
surface — the `--region` validator and error message, the default probe order, the
`start` banner, `doctor`, the `guide` / `companion` region hints, and the GUI
status row — so the story stays consistent everywhere. The removed `fi` region
stays removed.

### Thanks
Every change above came from external testers who ran v0.6.1 on real hardware and
reported carefully — above all the M4 Max tester whose deep feedback surfaced the
"Stop didn't stop xmrig" orphan and the Chinese-mode localization gap, and the
RTX 3080/4090 testers who surfaced the region-legibility confusion. Thank you.

## 中文

Alice Miner **v0.6.2** 是 v0.6.1 之上的矿工体验版。挖矿 lane、proof-of-possession、
credit-only 奖励、ed25519 签名自动更新全部不变 —— 变化的是客户端把"它在做什么"讲得
更清楚、一处真正修好的停止按钮、一个上手向导、一条自带矿机的路径,以及一个新区域。
每一项都源自在真实硬件上运行 v0.6.1 的外部测试者反馈。

**1. 终端 ↔ 仪表盘遥测同步(GUI)。**
当你从终端 CLI 运行矿工时,桌面应用现在会显示同一份实时画面。CLI 把它的实时快照镜像到
一个小遥测文件(原子覆盖、绝不追加;是 credit-only 的 Snapshot,不含任何地址相邻密钥、
也无 `paid_acu`),GUI 每约 900 ms 轮询一次,并通过既有快照路径折入仪表盘。终端一启动
应用就读到 **运行中**(在第一份快照之前),停止过程中显示 **停止中**,一旦遥测过期
(>10 秒 —— 终端关闭或 CLI 退出)便回到 **空闲**,而不是永远显示运行中。EN/中 切换现在
每帧镜像进共享核心,标题栏状态徽标与设置项标签因此本地化为中文(即"中文模式仍是英文"
的反馈)。

**2. 停止按钮现在真的会停下矿机(orphan-xmrig 修复)。**
一位 M4 Max 测试者反馈"我按了停止,但 xmrig 仍然满载在约 1200% CPU"。`stop` 现在是
**防孤儿**的,采用三层兜底、最精确者优先:CLI 父进程 pid(`miner-cli.pid`,干净路径)、
再到 **引擎子进程**(`miner-child.pid`,由监督器连同确切引擎二进制路径一起写入)、最后是
一个 unix 兜底,只匹配我们自带 xmrig 的确切路径。GUI 的停止现在运行自带的 CLI `stop`
(带这些兜底),而不是窗口内那个休眠引擎,并在退出时尽力停掉外部矿工 —— 不重复挖矿、
不留孤儿 xmrig。第二层的子进程 pid 兜底在**动手前会核验身份**:它重新确认目标 pid 的
命令行仍包含我们记录的引擎路径(unix 用 `ps`,Windows 用 `wmic`,未知时安全地判否),
因此一个操作系统已把编号 **重用** 给不相关进程的过期 pid 文件会被放过 —— 停止绝不会
误伤无辜进程。引擎无关(xmrig / SRBMiner / kawpowminer / AlphaMiner);兼容旧的仅含 pid
的文件。

**3. 区域透明化 + `doctor` 诊断(GPU-PRL lane)。**
一位测试者看到 PRL 通道从 Asia 跳到 US,却分不清"Asia 优先 + 自动切换"和"Asia 锁定"。
现在有效区域策略在各处都清晰可读,且**不做任何网络探测**地计算(从持久化设置 +
`ALICE_GPU_RELAY_REGION` 得出,因此展示它零往返、绝不二次探测 —— 引擎仍在启动时跑那唯一
一次真实 RTT 探测)。`start --lane prl` 会打印有效区域 **模式** 行与有效 **端点顺序**
(双语)。`doctor --lane prl` 新增三行 —— PRL 区域模式、PRL 区域来源(`region_lock` /
`last_good_region` / `ALICE_GPU_RELAY_REGION`,以及是否设置了 `ALICE_MINER_ENDPOINTS_JSON`,
仅存在性)、以及 PRL 有效端点。若某个已退役的 `fi` 中继因旧版 binary 或 endpoints-JSON
覆盖而泄漏进来,横幅与 `doctor` 都会连同确切提示标记它。GUI 新增一个只读"区域"状态行
(没有区域选择器 —— 区域通过 `start --region <tag>` 设置)。

**4. 首次上手向导(`guide`)+ 双语 `mining-guide.md`。**
新增 `alice-miner guide` —— 一个顾问,在第一分钟内讲清 Alice 挖矿到底怎么运作(是某个既有
币的真实份额,按难度加权的 6 小时排放,在 GPU/CPU/ASIC 三池间按 70/15/15 拆分),检测你的
硬件,并推荐一条 lane —— 它什么都不写、也不需要身份(与 `setup` 不同)。它随附一份新的
双语 `docs/mining-guide.md` 走查(如何运作 → 选择 lane → 自带矿机 → 平台注意/排障),
全程用 credit-only 的诚实框架,输出中任何地方都没有上游矿池主机、基金会地址或核心 IP。

**5. 自带第三方 pearlhash 矿机(`companion`)。**
PRL/Alpha 中继需要一个所有权证明,官方客户端在内部完成,而第三方矿机做不到。新增
`alice-miner companion` **在不运行任何矿机的前提下** 持有该证明:它在本地解锁你的 Alice
密钥,并在中继允许名单 TTL 内以刷新循环运行 `/m4/challenge → 签名 → /m4/verify` 握手,
在你把自己的矿机指向同一区域中继时,持续保持 `(你的地址, 设备)` 处于授权状态。你的私钥
绝不离开本机。companion 现在会**拒绝一个不是本机签名身份的 `--address`** —— 中继会用
已注册地址的公钥来验证 PoP 签名,因此注册任何其他地址产生的签名它永远无法验证,矿机会在
`code:24` 上无限循环(安全但静默)。不匹配现在会以双语、可操作的错误退出,列出两个地址,
并区分独立的 PRL 返现地址。

**6. 新增 EU 区域(GPU-PRL / Alpha)。**
`eu.aliceprotocol.org` 现在**已完全上线**(证书已签,行为与 `us`、`asia` 一致),并加入
编译区域集。pearlhash 区域现在是 **us / asia / eu**;EU 节点会自动就近连到更近的中继,你也
可以用 `start --region eu`(或 companion 的 `--region eu`)固定它。这个改动从单一真相源
(`REGION_HOSTS`)流向每一处派生面 —— `--region` 校验与错误信息、默认探测顺序、`start`
横幅、`doctor`、`guide` / `companion` 的区域提示、以及 GUI 状态行 —— 因此各处叙述保持
一致。已移除的 `fi` 区域保持移除。

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.2, like v0.6.0 and v0.6.1, is a **DRY / credit-only test build**.
It really mines and shows your live hashrate and **accepted shares as credit**, but
**`paid_acu = 0` — no real money is paid, no cryptocurrency and no fiat changes
hands, and nothing here is a promise, projection, or guarantee of earnings,
rewards, or returns.** Mining is permissionless with a bare Alice address — no
enrollment and no proof-of-possession are required for the open (XMR/RVN) lanes;
the pearlhash lanes use a possession proof only to bind shares to your address, not
to gate payment. The purpose of this build is exactly to let testers exercise the
download → configure → mine → view-payout path on real machines and confirm these
fixes, at zero real-money risk.

**中文。** v0.6.2 与 v0.6.0、v0.6.1 一样,是 **DRY / credit-only 测试版**。它会真实挖矿,
显示实时算力与**以 credit 记账的已接受份额**,但 **`paid_acu = 0` —— 不发放任何真钱,
不涉及任何加密货币或法币,本文档中的任何内容都不构成对收益、奖励或回报的承诺、预测或
保证。** 挖矿用一个裸 Alice 地址即可,是 permissionless 的 —— 开放(XMR/RVN)通道无需
报名、无需 proof-of-possession;pearlhash 通道用所有权证明只是为了把份额绑定到你的地址,
并非用来控制付款。本版本的目的正是让测试者在真实机器上跑通"下载 → 配置 → 挖矿 →
查看 payout"链路、验证这些修复,且零真钱风险。
