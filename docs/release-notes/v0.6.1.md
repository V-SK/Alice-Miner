## English

Alice Miner **v0.6.1** is a stability roll-up over v0.6.0. Same mining lanes,
proof-of-possession, credit-only rewards, and ed25519-signed auto-update — six
targeted fixes, all traced back to reports from external testers running the
v0.6.0 client on real hardware.

**1. Apple-Silicon hashrate + hardware detection (macOS).**
An M4 Max tester saw XMR/RandomX hashrate at roughly a third of a normal miner,
plus a detect screen reading 8 GB RAM and a blank CPU model. Two independent
bugs, reproduced and fixed on an M2 Max. The big one: on Apple Silicon a spawned
child **inherits the parent's background QoS clamp**, which parks RandomX on the
efficiency (E) cores and runs it ~10x slower whenever the miner UI is App-Napped,
occluded, or backgrounded — the engine is now explicitly taken out of the
background band before it execs (0.3 → 3.72 kH/s in the repro). The detect bug
was a `sysctl` invoked without an absolute path, which fails in a GUI `.app` /
minimal-env launch and collapsed both the RAM and CPU-model probes to their
fallbacks; detect now calls `/usr/sbin/sysctl` directly. No payout, PoP,
difficulty, or chain surface is touched.

**2. Windows Chinese output no longer mojibake (中文乱码).**
Traditional-Chinese Windows testers saw Chinese CLI text render as garbage
(e.g. `撖摨隞?`) unless they ran `chcp 65001` first. On a real console Windows
renders Chinese fine, but whenever output takes the byte path instead — redirected
to a file, or through a pipe-backed host like MSYS/mintty/VS Code/ConEmu — the
console decodes our UTF-8 bytes with its active code page (cp950/Big5) and mangles
them. The CLI now sets the console to UTF-8 (`SetConsoleOutputCP/CP(65001)`) as
the very first thing it does, so Chinese renders correctly out of the box. It is
a harmless no-op on the console path, on non-Windows, and when no console is
attached, and it adds no new dependency.

**3. Test suites no longer touch the real `~/.alice` (build hardening).**
This is a developer / build-integrity fix with no runtime behavior change, but
it protects something important: two confirmed leaks let `cargo test` write the
real `~/.alice` (wallet keystore / identity pointer / update-check file). Both
are closed — every test now runs against a throwaway identity directory, a
`cfg(test)`-only guard turns any accidental real-home fallback into a loud test
failure instead of a silent keystore clobber, and a regression test proves
identity creation stays inside its temp dir under concurrent pressure. Verified
on rustc 1.97 (CI) and 1.96 with the real `~/.alice` mtime unchanged after a
full run.

**4. GUI improves recovery from the remote-desktop white screen (Windows, GUI Beta).**
A tester on Windows + RTX 3080 over a **DeskIn** session reported AliceMiner.exe
opening to a solid-white window while the CLI worked fine — the classic
egui/OpenGL failure where a remote display driver hands the app a broken/software
GL context, so the window runs but never paints. The GUI now ships the Direct3D
(`wgpu`) backend alongside OpenGL. **On a genuine Windows RDP / Terminal-Services
session the switch to `wgpu` is automatic.** Mirror / console-sharing tools —
**DeskIn, AnyDesk, TeamViewer, Parsec, Sunflower** — are *not* auto-detected by
the OS remote-session flag, so for those set **`ALICE_GUI_RENDERER=wgpu`
manually** (a startup log now records the OS, session type, chosen renderer, and,
if a software rasterizer like *GDI Generic* / *llvmpipe* is detected, on-screen
guidance to switch). The headless **CLI always works** regardless. Real
remote-desktop runtime is still pending validation on a Windows test machine; the
fix is verified on macOS (both backends render every screen) with the Windows FFI
typechecked.

**5. Region memory, `--region` lock, and failover pre-flight (GPU-PRL lane).**
A GPU-PRL tester reported that after a restart the miner didn't resume the region
that had been working (Asia) — it auto-switched to an unavailable relay and
stopped in error, with nothing saying whether that was auto-failover or a manual
choice. The region choice is now persistable, lockable, and honestly labeled:
the client remembers the last-good region and prefers it on restart; `start
--region <us|asia>` **locks** a region (single-region plan, no auto-failover),
`--region auto` clears the lock, and an unknown value is a usage error. Before
rotating away from a failing region the watchdog now **pre-flights** candidate
regions (a bounded TCP connect) and only rotates to one that actually answers —
never blindly into a dead region — and the status line is labeled
(`auto-failover: <from> → <to>` for a real change, `region <r> locked — retrying`
for a lock). The conservative default is unchanged: no pin and no history still
means lowest-RTT probe.

**6. Dead Finland (FI) region relay removed (GPU-PRL / Alpha).**
`fi.aliceprotocol.org` shipped in the region host-set but was **never
provisioned** — it resolves NXDOMAIN, so every client burned a full RTT-probe
timeout (~1.5 s) on a dead host at startup, and `ALICE_GPU_RELAY_REGION=fi` /
`--region fi` could force the lane onto it. The region set is now **us / asia**
only, eliminating that pointless startup probe. Nothing else changes; if a real
Finland relay is stood up later it can be added back in one line.

### Thanks
Every fix above came from external testers who ran v0.6.0 on real hardware and
reported carefully — the M4 Max hashrate/detect report, the Traditional-Chinese
Windows mojibake reports, and the RTX 3080 DeskIn soak tester who surfaced both
the white-screen and the region-failover behavior. Thank you.

## 中文

Alice Miner **v0.6.1** 是 v0.6.0 之上的稳定性汇总版。挖矿 lane、proof-of-possession、
credit-only 奖励、ed25519 签名自动更新全部不变 —— 六处定点修复,全部源自外部测试者
在真实硬件上运行 v0.6.0 客户端后的反馈。

**1. Apple Silicon 算力 + 硬件检测(macOS)。**
一位 M4 Max 测试者反馈 XMR/RandomX 算力只有正常矿工的约三分之一,同时 detect 页面
显示 8 GB 内存、CPU 型号空白。两个独立 bug,已在 M2 Max 上复现并修复。主因:Apple
Silicon 上,被启动的子进程会**继承父进程的后台 QoS 钳制**,一旦矿工 UI 被 App Nap /
遮挡 / 切到后台,RandomX 就被赶到能效(E)核上、慢约 10 倍 —— 现在引擎在 exec 前会显式
脱离后台优先级带(复现中 0.3 → 3.72 kH/s)。detect 的 bug 是 `sysctl` 未用绝对路径调用,
在 GUI `.app` / 精简环境启动时会失败,导致内存与 CPU 型号两项探测同时回落到兜底值;
detect 现在直接调用 `/usr/sbin/sysctl`。不触碰任何 payout / PoP / 难度 / 链的代码面。

**2. Windows 中文输出不再乱码。**
繁体中文 Windows 测试者看到中文 CLI 文本显示为乱码(如 `撖摨隞?`),必须先 `chcp 65001`
才正常。在真正的控制台上 Windows 能正确渲染中文,但一旦输出走字节路径 —— 重定向到文件,
或经由 MSYS/mintty/VS Code/ConEmu 这类管道宿主 —— 控制台就会用当前代码页(cp950/Big5)
去解码我们的 UTF-8 字节,从而乱码。CLI 现在会在做任何事之前第一时间把控制台设为 UTF-8
(`SetConsoleOutputCP/CP(65001)`),中文开箱即正确。它在控制台路径、非 Windows、以及无
控制台附着时都是无害空操作,且不引入任何新依赖。

**3. 测试套件不再触碰真实 `~/.alice`(构建加固)。**
这是一处开发者 / 构建完整性修复,无运行时行为变化,但它保护的东西很重要:两处已确认的
泄漏会让 `cargo test` 写入真实 `~/.alice`(钱包 keystore / 身份指针 / 更新检查文件)。两处
均已封堵 —— 每个测试现在都对着一个用后即弃的身份目录运行;一个仅 `cfg(test)` 的守卫会把
任何"意外回落到真实 home"变成响亮的测试失败,而不是悄无声息地覆盖 keystore;并新增回归
测试证明并发压力下身份创建始终留在其临时目录内。已在 rustc 1.97(CI)与 1.96 上验证,
整轮运行后真实 `~/.alice` 的 mtime 未变。

**4. GUI 改进对远程桌面白屏的恢复(Windows,GUI Beta)。**
一位 Windows + RTX 3080、经 **DeskIn** 会话的测试者反馈 AliceMiner.exe 打开是一片纯白窗口,
而 CLI 正常 —— 这是经典的 egui/OpenGL 远程失败:远程显示驱动给了应用一个损坏/软件 GL
上下文,窗口在跑却从不绘制。GUI 现在在 OpenGL 之外同时打包 Direct3D(`wgpu`)后端。
**在真正的 Windows RDP / 终端服务会话下,切到 `wgpu` 是自动的。** 而镜像 / 投屏类工具 ——
**DeskIn、AnyDesk、TeamViewer、Parsec、向日葵** —— 不会被系统的远程会话标志识别,因此这类
工具请**手动设置 `ALICE_GUI_RENDERER=wgpu`**(现在有一份启动日志记录操作系统、会话类型、
所选渲染器;若检测到 *GDI Generic* / *llvmpipe* 之类软件光栅化器,还会在屏上给出切换提示)。
无头 **CLI 始终可用**。真实远程桌面的运行时表现仍待 Windows 测试机验证;本修复已在 macOS
上验证(两个后端都能渲染每个界面),Windows FFI 已通过类型检查。

**5. 区域记忆、`--region` 锁定、故障切换预检(GPU-PRL lane)。**
一位 GPU-PRL 测试者反馈:重启后矿工没有恢复到之前能用的区域(Asia),而是自动切到不可用的
中继并报错停止,且没有任何标识说明这是自动切换还是手动选择。区域选择现在可持久化、
可锁定、且诚实标注:客户端会记住上一个可用区域并在重启时优先使用;`start --region
<us|asia>` **锁定**一个区域(单区域方案,不自动故障切换),`--region auto` 清除锁定,
未知取值报使用错误。在从故障区域切走之前,看门狗现在会对候选区域做**预检**(有界 TCP
连接),只切到真正有响应的区域 —— 绝不盲目切进死区域 —— 且状态行有标注(真实切换显示
`auto-failover: <from> → <to>`,锁定显示 `region <r> locked — retrying`)。保守默认不变:
无 pin 且无历史,仍走最低 RTT 探测。

**6. 移除未部署的 Finland(FI)区域端点(GPU-PRL / Alpha)。**
`fi.aliceprotocol.org` 一直在区域主机集里,却**从未部署** —— 它解析为 NXDOMAIN,
导致每个客户端在启动时对一个死主机白白耗掉一整个 RTT 探测超时(~1.5 秒),且
`ALICE_GPU_RELAY_REGION=fi` / `--region fi` 可能把 lane 强制切到它上面。区域集现在
只剩 **us / asia**,消除了这段启动期无谓探测。其余一切不变;日后若真的搭建 Finland
中继,一行即可加回。

以上每一处修复都来自在真实硬件上运行 v0.6.0 并认真反馈的外部测试者 —— M4 Max 的算力/检测

## Honesty note / 诚实声明 (credit-only)

**English.** v0.6.1, like v0.6.0, is a **DRY / credit-only test build**. It really
mines and shows your live hashrate and **accepted shares as credit**, but
**`paid_acu = 0` — no real money is paid, no cryptocurrency and no fiat changes
hands, and nothing here is a promise, projection, or guarantee of earnings,
rewards, or returns.** Mining is permissionless with a bare Alice address — no
enrollment and no proof-of-possession are required in this phase. The purpose of
this build is exactly to let testers exercise the download → configure → mine →
view-payout path on real machines and confirm these fixes, at zero real-money
risk.

算力与**以 credit 记账的已接受份额**,但 **`paid_acu = 0` —— 不发放任何真钱,不涉及任何
加密货币或法币,本文档中的任何内容都不构成对收益、奖励或回报的承诺、预测或保证。** 挖矿
在本阶段是 permissionless 的,用一个裸 Alice 地址即可,无需报名、无需 proof-of-possession。
本版本的目的正是让测试者在真实机器上跑通"下载 → 配置 → 挖矿 → 查看 payout"链路、验证这些
修复,且零真钱风险。
